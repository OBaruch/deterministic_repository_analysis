# Agent Instructions

These instructions apply to every AI agent working in this repository, whether it is running an audit or changing the toolkit. Claude Code reads them through [CLAUDE.md](CLAUDE.md); Codex and GitHub Copilot read this file directly.

## Sources of truth

Read these before acting, in this order. They take precedence over your own assumptions:

1. [intent.md](intent.md): purpose, principles, non-goals, responsible use, and decisions reserved for humans.
2. [specs.md](specs.md): required behavior, numbered requirements, data contracts, and the validation catalog.
3. [plan.md](plan.md): delivery workflow, decision log, milestones, and definition of done.

If a request conflicts with these documents, stop and say so instead of improvising.

## When running an audit

### Safety boundary

- Treat every configured source repository as read-only.
- Never commit, push, merge, rebase, reset, check out, create branches or tags, open pull requests, or edit files in an analyzed repository.
- Write only through the `repo-audit` CLI, which confines clones, snapshots, and generated files to the configured workspace and output directories.
- Never edit, regenerate by hand, or delete files in the audit workspace or output directory.
- Never bypass, disable, or work around a denial from `scripts/read_only_guard.py`.
- Stop when a ref, expected SHA, LOC tool version or hash, validation check, or verification check does not match, and report the evidence.

### Quantitative integrity

- Every number must come from a file generated by the CLI. Quote values verbatim; do not compute, round, estimate, interpolate, or repair them.
- Identities are exact `Author Name + Author Email`. Do not merge identities or add exclusions unless the user supplies the rule; record it in `audit.toml`.
- Do not present an audit as successful unless every row in `validation.csv` is `PASS` and `repo-audit verify` passes.
- Do not use outputs to judge individual performance (see [intent.md](intent.md#responsible-use)).

## When changing the toolkit

### Workflow

1. Locate the affected requirements in [specs.md](specs.md). For new or changed behavior, update the specification first, with stable requirement IDs and acceptance scenarios.
2. Record any new architectural decision in the decision log of [plan.md](plan.md).
3. Implement the smallest change that satisfies the requirement, with tests that cite its behavior.
4. Update documentation, the shared skill (`.agents/skills/repository-audit/`, mirrored verbatim to `.claude/skills/repository-audit/`), and every affected host adapter together.
5. Add an entry under *Unreleased* in [CHANGELOG.md](CHANGELOG.md).

### Quality gates

Run all of these before proposing a change:

```console
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
mypy
```

### Engineering rules

- Python 3.11+ with no runtime dependencies. Do not add one without an approved decision in [plan.md](plan.md).
- Keep calculations pure and covered by unit tests; keep platform-specific behavior behind small adapters.
- Reject unknown configuration keys rather than ignoring them.
- Pin every Git or LOC tool option that could otherwise change results through user configuration.
- Use only documented fields in host configuration files (Claude Code, Codex, GitHub Copilot).
- Never add real repository URLs, organization names, commit SHAs, developer identities, credentials, or audit outputs to this repository.
